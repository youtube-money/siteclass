# سایت کلاسی — نسخهٔ PHP (برای هاست اشتراکی ایرانی)

## چرا این استک؟
- بدون هیچ مرحلهٔ build — فایل‌ها رو آپلود می‌کنی و همون‌جا کار می‌کنه
- روی تقریباً هر هاست اشتراکی ارزون ایرانی جواب می‌ده (PHP + MySQL همه‌جا هست)
- فرانت و بک‌اند روی یه دامنه‌ن، پس مشکل فیلترشدن/CORS نداره
- فایل‌های سنگین (عکس، جزوه، صدا) روی گوگل‌درایوت می‌مونن، نه روی هاست — چون فضای هاست ارزون محدوده

## ساختار پروژه
```
class-site-php/
├── api/           ← بک‌اند PHP (فقط فایل‌های .php، مستقیم قابل اجرا روی هر هاست)
├── assets/
│   ├── css/style.css   ← سیستم طراحی (رنگ‌ها، شیشه‌ای، انیمیشن‌ها)
│   └── js/api.js       ← ارتباط با بک‌اند
├── sql/schema.sql ← اسکیمای دیتابیس MySQL
├── login.html
├── dashboard.html
├── chat.html
├── schedule.html
└── index.php      ← ریدایرکت خودکار به لاگین یا داشبورد
```

## چیزی که توش هست
- **ورود/ثبت‌نام** با سشن امن PHP
- **چت گروهی + خصوصی** با عکس و پیام صوتی
- **برنامهٔ کلاسی**
- **آپلود فایل** (عکس/جزوه) روی گوگل‌درایو
- **برنامه‌ریزی بیرون‌رفتن** (ایده، زمان‌بندی، چت کوتاه)
- **ویدیوهای آموزشی** (آپارات/یوتیوب/درایو)
- **تکلیف و پروژه** با کلید API شخصی هر دانش‌آموز
- **دونیت**
- **پرامپت‌ساز جزوه**
- **بازی‌های آماده** (مار، تتریس، حدس‌عدد) + **بازی‌های ساختهٔ بچه‌ها** (اجرا توی iframe ایزوله برای امنیت)

## راه‌اندازی گوگل‌درایو (برای آپلود فایل)

1. برو به [Google Cloud Console](https://console.cloud.google.com)، یه پروژه بساز، «Google Drive API» رو فعال کن.
2. Credentials → Create Credentials → Service Account بساز.
3. وارد سرویس‌اکانت شو → Keys → Add Key → Create new key → نوع JSON. دانلودش کن.
4. توی گوگل‌درایوت یه پوشه بساز، Share کن با ایمیل سرویس‌اکانت (`client_email` توی فایل JSON) با دسترسی Editor.
5. توی `api/config.php`:
   - `GOOGLE_CLIENT_EMAIL` = همون `client_email`
   - `GOOGLE_PRIVATE_KEY` = کل مقدار `private_key` از فایل JSON (شامل خطوط BEGIN/END)
   - `GOOGLE_DRIVE_FOLDER_ID` = شناسهٔ پوشه (از آدرس URL پوشه، بعد از `folders/`)

## راه‌اندازی روی هاست ایرانی

1. **خرید هاست:** یه هاست اشتراکی لینوکسی با پنل cPanel بخر که PHP (نسخهٔ ۸ به بالا) و MySQL داشته باشه — تقریباً همهٔ هاست‌های ارزون ایرانی (مثل آی‌آر هاست، پارس‌پک، میهن‌وب‌هاست و مشابه) این‌ها رو دارن.

2. **ساخت دیتابیس:** توی cPanel برو به «MySQL Databases»:
   - یه دیتابیس جدید بساز (مثلاً `classsite`)
   - یه یوزر دیتابیس بساز و پسورد قوی بذار
   - یوزر رو به دیتابیس با دسترسی «All Privileges» وصل کن
   - این سه تا (اسم دیتابیس، یوزر، پسورد) رو یادداشت کن

3. **اجرای اسکیما:** توی cPanel برو به «phpMyAdmin»، دیتابیسی که ساختی رو انتخاب کن، برو تب «SQL» و به‌ترتیب این پنج فایل رو پیست و اجرا کن: `sql/schema.sql`، بعد `sql/schema-phase2-4.sql`، بعد `sql/schema-phase5.sql`، بعد `sql/schema-phase6.sql`، بعد `sql/schema-phase7.sql` (ترتیب مهمه چون فایل‌های بعدی به جدول‌های قبلی وابسته‌ن).

4. **تنظیم `api/config.php`:** این فایل رو باز کن و مقادیر `DB_NAME`، `DB_USER`، `DB_PASS` رو با چیزی که مرحلهٔ ۲ ساختی جایگزین کن. `SESSION_SECRET` رو هم با یه رشتهٔ تصادفی طولانی پر کن.

5. **آپلود فایل‌ها:** از طریق «File Manager» توی cPanel یا با یه برنامهٔ FTP (مثل FileZilla)، کل محتوای این پوشه رو بریز توی پوشهٔ `public_html` (یا هر پوشه‌ای که هاستت روت سایت حساب می‌کنه).

6. **تست:** آدرس سایتت رو باز کن — باید بره صفحهٔ ورود. یه حساب بساز، وارد شو، چت و برنامه رو تست کن.

7. **ادمین کردن خودت:** توی phpMyAdmin، جدول `users` رو باز کن، ردیف خودت رو پیدا کن، ستون `role` رو از `student` به `admin` تغییر بده تا بتونی برنامهٔ کلاسی اضافه کنی.

## طراحی ریسپانسیو
همهٔ صفحات موبایل‌فرندلی‌ان — نوار بالای صفحه روی گوشی به منوی همبرگری (☰) تبدیل می‌شه، جدول‌ها و فرم‌ها روی صفحهٔ کوچیک درست می‌شینن، و پس‌زمینهٔ انیمیشنی روی موبایل سبک‌تر (کم‌مصرف‌تر) اجرا می‌شه.

## چیزی که عمداً توش نیست
تماس تصویری/صوتی زنده (مثل گوگل‌میت) رو عمداً حذف کردیم، چون هم روی هاست ارزون سنگینه و هم به سرویس‌های خارجی نیاز داشت که ممکنه فیلتر بشن. به‌جاش، **پیام صوتی توی چت** (ضبط و ارسال، مثل واتساپ) هست که کاملاً کار می‌کنه و از همون گوگل‌درایو استفاده می‌کنه.

## فاز ۵ — نقش‌ها و بخش‌های تکمیلی
- **نقش‌ها:** حالا سه نقش داریم: `student` (دانش‌آموز عادی)، `special` (نقش ویژه)، `admin`. تغییرش از پنل ادمین انجام می‌شه.
- **حساب کاربری:** هر کاربر آواتار (اموجی)، نام نمایشی، و بیو داره. رنگ تم پروفایل فقط برای نقش `special`/`admin` باز می‌شه.
- **شبکهٔ اجتماعی:** فقط نقش `special`/`admin` توی منو می‌بینتش و بهش دسترسی داره — این محدودیت هم سمت فرانت (مخفی کردن لینک) و هم سمت بک‌اند (`requireRole`) اعمال شده، پس یه دانش‌آموز عادی حتی با حدس زدن آدرس هم نمی‌تونه واردش بشه.
- **رفع اشکال:** برای همه باز — گزارش مشکل + کامنت‌گذاری برای کمک به حلش.
- **دروس:** ادمین درس تعریف می‌کنه؛ همه می‌تونن زیرش محتوا اضافه کنن.
- **جزوه:** بر اساس کتاب/پودمان دسته‌بندی می‌شه. دو مسیر داره: آپلود فایل، یا «ساخت با AI» — که یه پرامپت آماده می‌ده تا همراه با عکس جزوهٔ دست‌نویس به ChatGPT بدی، و نتیجه رو برمی‌گردونی روی سایت.
- **بازی‌ها:** حالا هم آپلود فایل HTML و هم پیست‌کردن کد رو پشتیبانی می‌کنه، + یه لیدربورد کلی که امتیاز بازی‌های آماده (مار/تتریس/حدس‌عدد) و بازی‌های بچه‌ها رو نشون می‌ده.
- **کلیدهای API سراسری (پنل ادمین):** تا ۳ کلید می‌تونی اضافه کنی؛ یکی‌شون رو می‌تونی «دستیار» (پشتیبانی سایت + کمک به کنترل بچه‌ها) مشخص کنی، و یه گزینه برای حافظهٔ مشترک بین کلیدها توی بخش دروس هست.
- **دونیت:** به‌جای لینک پرداخت (که کارمزد می‌گیره)، شمارهٔ کارت مستقیم نمایش داده می‌شه.
- **برنامهٔ کلاسی:** ادمین می‌تونه تعداد درس در هر روز رو تنظیم کنه (پیش‌فرض ۴).

⚠️ **نکتهٔ مهم دربارهٔ «دستیار ادمین»:** فقط جای تنظیم کلیدش رو ساختیم؛ خودِ منطق (چه‌کارهایی دقیقاً این دستیار برای کنترل بچه‌ها انجام بده — مثلاً هشدار خودکار، گزارش رفتار، پیام‌رسانی) هنوز پیاده نشده، چون نیاز به مشخص‌کردن دقیق‌تر داره. هروقت خواستی وارد این بخش بشیم، بگو دقیقاً چه قابلیت‌هایی می‌خوای.

## فاز ۶ — چت‌بات، دستیار کدنویسی، و حافظهٔ مشترک

حالا هر کدوم از ۳ کلید API سراسری یه نقش مشخص داره (توی پنل ادمین انتخاب می‌شه):

- **🎧 پشتیبانی/دستیار ادمین** — همون که بالا توضیح داده شد (فقط جای تنظیمش آماده‌ست)
- **🤖 چت‌بات** — توی چت گروهی، هر پیامی که با `/بات` شروع بشه (مثلا: `/بات فردا امتحان داریم؟`) رو دستیار جواب می‌ده. جواب از حساب مجازی «دستیار کلاس» توی همون چت گروهی فرستاده می‌شه.
- **💻 دستیار پیش‌فرض کدنویسی** — توی بخش «تکلیف و پروژه»، تب «نوشتن کد» یه دکمهٔ «کمک از AI» داره که با همین کلید (بدون نیاز به کلید شخصی) کد رو بررسی و راهنمایی می‌کنه. این دستیار **حافظه نداره** (هر بار مستقل جواب می‌ده)، چون یه کلید مشترک بین کل کلاسه و نباید مکالمهٔ دانش‌آموزها با هم قاطی بشه.

**دستیار شخصی بچه‌ها:** وقتی یه دانش‌آموز کلید API خودش رو برای یه پروژه ثبت می‌کنه، زیرش یه جعبهٔ گفتگو ظاهر می‌شه. این دستیار **حافظه داره و بین همهٔ پروژه‌های خودِ همون دانش‌آموز مشترکه** — یعنی اگه توی یه پروژه چیزی بهش گفته باشه، توی پروژهٔ دیگه هم یادشه. این حافظه فقط مال خودشه، با بقیه قاطی نمی‌شه.

## فاز ۷ — ادیتور کد واقعی + رفع باگ امتیاز بازی‌ها

- **ادیتور کد:** تب «نوشتن کد» توی «تکلیف و پروژه» حالا یه ادیتور واقعی داره (CodeMirror) با شماره‌خط، رنگ‌بندی سینتکس، و انتخاب زبان (Python/JavaScript/HTML/CSS/++C/Java). کد هر دانش‌آموز خودکار ذخیره می‌شه (حدود ۱ ثانیه بعد از توقف تایپ) و با رفرش صفحه از دست نمی‌ره.

- **رفع باگ امتیاز بازی‌های بچه‌ها:** بازی‌های آپلودی/AI-ساز توی یه iframe کاملاً ایزوله اجرا می‌شن که عمداً به کوکی/شبکهٔ سایت دسترسی نداره (برای امنیت). یعنی هر `fetch` مستقیم از داخل خودِ بازی، بی‌صدا شکست می‌خورد و امتیاز ذخیره نمی‌شد. حالا اصلاح شده: بازی با `window.parent.postMessage(...)` امتیازش رو به صفحهٔ اصلی می‌فرسته، و صفحهٔ اصلی (که به session دسترسی داره) اونو ذخیره می‌کنه. پرامپت AI-ساز بازی هم آپدیت شد تا این روش رو دقیق توضیح بده — یعنی از الان، بازی‌های جدیدی که با اون پرامپت ساخته بشن، امتیازشون درست ثبت می‌شه. بازی‌هایی که قبلاً با پرامپت قدیمی ساخته شدن رو باید دوباره بسازی یا دستی همین خط رو بهشون اضافه کنی.

## نکتهٔ امنیتی
فایل `api/config.php` حاوی رمز دیتابیسته — هیچ‌وقت این فایل رو با مقادیر واقعی، جایی عمومی (مثل یه ریپوی گیت‌هاب پابلیک) آپلود نکن. اگه می‌خوای کد رو روی گیت‌هاب بذاری، این فایل رو با یه `.gitignore` کنار بذار و فقط یه نسخهٔ نمونه (`config.example.php`) رو آپلود کن.
